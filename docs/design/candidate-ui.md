# 候选窗口设计

## 布局

候选固定横向排成一行，页码在行尾：

```text
1 计算机  2 电脑  3 计算  4 计算器          1/3
```

顶部是一行拼音（preedit），见下文「拼音行」。候选数量由 `[general] page_size` 控制（1–9），设置入口放在「候选窗口」页。

## 视觉层级

- 候选词：较大、较深
- 翻译：较小、较浅
- 序号：弱化显示
- 当前候选：轻量高亮

翻译永远不应该抢夺候选词本身的注意力。它只是一个 annotation，而不是另一套候选系统。

## 翻译 annotation 的规则（已停用）

译文相关的能力（Learning Language、生词标记、释义兜底、翻译选中文字）在 Windows 上不提供；
上游的规则保留在 git 历史里，Core 里相关代码见 CLAUDE.md 的目录地图。

## 技术选型

候选窗口本质上只有四个原语：一行 (序号, 候选词)、一块高亮、拼音行、跟随光标定位。
这么小的 UI 不值得引入跨平台 GUI 框架。缺省由一个 Rust 自绘渲染器出位图、壳只贴图（主题因此像素级一致），见 [rendering.md](rendering.md)；下表是壳的窗口与退路的画法。

| 平台 | 方案 | 理由 |
|---|---|---|
| Windows | Server 进程里 GDI 画到 layered window（`server/src/ui/layered/`） | 避开 WebView2 依赖（水杉 issue #68 就是安装环境缺 WebView2）。原计划改 Direct2D + DirectWrite，已被自绘渲染器取代 |

不选的方案及原因：

- **WebView（水杉 HTML UI 的路线）**：样式最自由，但常驻进程多一个渲染引擎，首次弹窗有可见延迟，
  且引入平台运行时依赖。候选框是「打字时每秒弹好几次」的 UI，延迟比样式重要。
- **egui / iced / GPUI 等 Rust GUI 框架**：它们假设自己拥有窗口和事件循环，
  和「非激活浮层」这种系统级窗口语义打架，为几百行绘制引入整套框架不划算。

主题化通过主题文件（字体、字号、配色、行距、圆角、阴影、透明、渐变、布局）实现，不提供 HTML/CSS 皮肤；主题渲染的方向见 [rendering.md](rendering.md)。

## 平台层的职责

候选窗口由平台层绘制，但候选内容与顺序全部来自 Core。
平台层拿到的是已经排好序的候选列表，只负责画。

## 按键约定（Windows）

| 按键 | 行为 |
|---|---|
| 字母、`'` | 在光标处插入 |
| 空格 | 上屏高亮候选；无候选时上屏拼音 |
| 1 到 9 | 上屏当前页第 N 个 |
| 回车 | 上屏拼音本身 |
| 退格 / Delete | 删光标前 / 后一个字母 |
| Esc | 清空 |
| 上 / 下 | 移动高亮，到页边自动翻页；第一项再按上不动 |
| 左 / 右、Home / End | 移动拼音光标（不切模式）。光标停在中间时候选只按光标前的拼音算（`ni|hao` 出 你），上屏后剩余拼音留着、光标落到末尾；光标在开头或末尾按整段算 |
| PageUp / PageDown、翻页键对（配置 `[general] page_keys`，缺省 `[` `]`，可选 `,` `.` 或 `-` `=`；选后者时组句中的 `-` 是翻页、不再进英文直输段） | 翻页。每页几个由 `page_size` 定（1–9） |
| 半角标点（`is_ascii_punctuation`，翻页键除外；Shift+数字已被删候选键截走） | 组句中敲它进入**英文直输段**：`no-way` `hello,` `dui'ma?` 整段原样显示，之后的可见字符（含数字、大写）都追加，回车原样上屏，空格原样上屏后空格本身也交给应用（`hello, world` 的空格要在），Esc 清掉。中文模式下就能打带标点的英文句子；代价是没有了「拼音 + 标点 = 上屏候选 + 全角标点」，要先空格再打标点 |
| Tab | 交给应用（缩进 / 跳焦点） |
| 修饰键 + 数字（Shift 删候选） | **只在组句中认**。不在组句时 Shift+4 就是普通的 `$`，走中文标点规则出 ￥（Shift+1 ！、Shift+6 ……、Shift+9 Shift+0 （ ））；曾经在这里被截走后原样还给应用，全角转换就漏了 |
| 按住 Shift 打的大写字母 | 先把拼音原样上屏，再原样交给应用（临时打英文） |
| Shift + 数字（可改） | **删掉当前页第 N 个候选**：自己造的词（用户词）整个删掉，本地不再出；词库里的词清掉对它的全部学习（选择次数、各输入串下的选择、个人 n-gram 里与它有关的转移），回到原来的排序；整句 / 快捷候选 / emoji 没什么可删。删完重新查一遍，结果那句话（「已删除用户词「X」」）灰字显示在拼音行右侧，敲下一键就没了；那格没有候选就吞掉按键。修饰键在 `[shortcut] delete_candidate`（缺省 Shift，空则退回缺省）。代价是组句中 Shift+1 不再是「上屏 + ！」，要先上屏；Core `Engine::forget` → `Learner::forget` / `forget_english` |

### 整句转换（离线）

最优切分至少两个音节、且最优路径不止一个词时，整句放在第一位（空格上屏的就是它），`CandidateKind::Sentence`：
`jintiantianqihenhao` → 今天天气很好，`womenyiqiqukaifa` → 我们一起去开发。整段本身是词库里的词时不出整句。
打分是静态 bigram（`qingjian-lm`）与个人 n-gram（二元 + 三元，看前两个词）插值。简拼位置照转（`jttqhh` → 今天天气很好，`wjdzjsg` → 我觉得自己是个），
每个简拼格子按前缀多留一些词、由语言模型挑读音；两字母简拼多半还是词（`sj` 时间），单词路径得分高就不出句子。
全拼句子末尾未打完的音节至少两个字母才算进句子（`woxiangs` 多半是没打完的 shuo），前面已有简拼的句子末尾单字母就是一个音节（`wxq`）。
有音节连单字都查不到（只能拿拼音占位）的不出句子；英文词的位置看 `Engine::chinese_first`（配置 `[general] chinese_first`，缺省关）：
关着时整段是英文词或不像拼音带出的英文补全排在句子前面（`hello` 先英文再 荷兰咯）；开着时整句先插、英文词紧随其后排第二（`hello` 先 荷兰咯 再 hello）。
缺省关是回放定的：9241 词 / 269 条英文上屏的冻结日志上，缺省开英文首选 82.5% → 7.1%，常在中文模式里打英文词的人被明显伤到；关着与改前完全一致。
上屏按音节消耗拼音，路径上的词逐条记进个人 n-gram（`user-ngram.tsv`），不记词频。

**句末英文词**（`Engine::split_english_tail`，`query::EnglishTail`）：整段末尾是英文词表里的词、前面能切成完整拼音时，
整句是头段的转换加上那个词（`woxiangxuehaorust` → 我想学好rust），排第一，`Query.tail` 是尾段字母（拼音行 `wo'xiang'xue'hao'rust`），
词级候选只按头段查。整段字母根本切不成拼音的（`wodetv` 的 v、`woyongvim`）直接按英文读；整段也能读成拼音的
（`woxiangxuehaorust` 读成 … ru s… t… 简拼、`wodedatabase`）两种读法比分：头段整句分 + 英文词 log 概率（wordfreq Zipf 换算，
没词频按 Zipf 3）− 切换代价（`ENGLISH_SWITCH_PENALTY` 3 nat，拍的）要高过整段按拼音读的整句（`sentence::convert_whole`，
末尾单字母也读，`huoz` → 或者，两边覆盖同样多的字母才公平），赢了英文读法排第一、拼音读法第二，输了英文读法不出
（`womenqubeijing` 只有 我们去北京，`diaoyong` 不出 掉Yong）。尾段自己是完整拼音的（`fan`）要至少 4 个字母，
两个字母的尾段只认缩写词（ID / TV）和个人表里的词；整段是英文词（`agent`）、拼音不像话时能纠错（`shiide` → 是的）或有英文补全
（`releas`）的不切。同时满足的取最长尾段。上屏时英文词是路径上最后一个词（音节就是敲的字母），进个人 n-gram，
并记进个人英文词表。回放（2026-09-08，4867 条）与改前持平：词 86.0% / 整句 89.3% / 英文 69.8%。
只认句末，夹在中间的英文（`wozaidebugzhege`）要等词图上加英文边。

**越用越像自己**：连续上屏的词（整句里的、或一个个选的）都记成「前词 → 后词」，同时记「前二词 前词 → 后词」；`qingjian` 里选过两次 青 + 简，
再打 `qingjian` 整句就直接出 青简（个人转移压过静态模型里的 请见）。三元分辨二元混在一起的接续：「我想」后面选过几次 区，
`woxiangqu` 就出 我想区，而「不想」后面照旧。标点、回车上屏拼音、切应用都断句，之后的词按句首记。
**自动造词**：自己连着选出的两个词合起来词库里没有（不超过 4 个字），同一段拼音里连着选两次、或分两段打三次，
就记成用户词（`user-words.tsv`），之后按词出、靠选择次数排前。

### 英文模式：纯直通

英文模式（单击 Shift 切的持久模式，或 Caps Lock 亮着）下敲的字母**不进缓冲区**，由壳直接插进输入框（大小写按 `shift XOR caps`），
不组句、不出候选窗；空格、回车、Tab、方向键、数字键都是它们本来的意思，只有标点还按英文那份全角设置转。
`apply_english`（`dispatch/key/input.rs`）就这几行：组句中切过来的先 `take_raw` 把拼音原样上屏，再插字母。

0.1.5 之前这里给过英文词表的补全与拼错纠正（Tab 与上下键选词，`[general] english_candidates` 开关，按应用的 `[apps] english_candidates_off` 名单）。
**整条路径连同两个开关一起删掉了**：切到英文模式就是「我现在要打英文」，这时候弹候选框与这个意图相反；
真要靠英文词表，中文模式下的中英混输已经给了（见下），不必切模式。删开关而不是改缺省，是因为老配置文件里已经写着 `true`，改缺省对现有用户无效；
两个键现在读到当没有（`retired_english_candidate_keys_are_ignored`）。Core 的 `english::suggest` 与个人英文词表照旧，供中英混输用。

**个人英文词表**（`user-english.tsv`，`词\t次数`）：随包词表只有两万多词，`gist`、`kubectl` 这类不在里面的词以前永远出不了候选。
现在中文模式下原样上屏的字母串只要像英文词——纯字母、至少两个，还要**切不成完整拼音**（`hao` 回车多半要的是字母本身，不学；
`gist` / `python` / `hello` 切不干净才是英文）——就记进个人词表，选中英文候选也记。英文候选由个人表 + 随包表一起出，
个人表在前：精确词取第一个有的，补全与纠正合在一起按选过的次数、词频排（`Engine::english_lists`、`english::suggest` 收词表列表）。
所以 `gist` 回车一次，下次敲 `gist` 它就是首选。

### 英文补全与 emoji

- **英文补全**：整段输入切成的拼音「不像话」（切不动、或非末尾有简拼 / 残缺音节：`compa` → `co'm'pa`、`impor` 连第一个字母都切不动）
  且至少 3 个字母时，除了整段正好是的英文词，还出词表里该前缀下最常用的 3 个（`compa` → company / companies / compared），
  紧跟在精确词之后、排在拼音候选前。干净的拼音（`xian`、`shan`）不补全，免得每个音节都冒英文。词频来自 wordfreq（`tools/corpus/english_frequency.py`）。
- **emoji**：前 5 个中文 / 英文候选里有配 emoji 的，emoji 紧跟在那个词后面（`ku` → 哭 😢 😭，`smile` → smile 🙂 😊），右侧标注对应的词；
  每个词最多 2 个、一次最多 3 个，`CandidateKind::Emoji`，上屏按那个词的音节消耗拼音（英文词带出的对应整段输入）、不记学习。
  数据是 Unicode CLDR 中文与英文 annotations（`assets/emoji/emoji-zh.tsv`、`emoji-en.tsv`，Unicode License v3，可发布，加载时合成一张表），
  `dict-convert emoji --language zh|en` 生成：单字词只收名字里含这个字的 emoji，名字里含这个词的靠前、名字越短越靠前。
  日文表要等有日语输入模式再说。

### 双拼（默认关，`[general] shuangpin`）

四套方案：小鹤（`xiaohe`）、自然码（`ziranma`）、微软（`microsoft`）、搜狗（`sogou`）。键位表在 Core `shuangpin::table`，
按 Rime 的 `double_pinyin*.schema.yaml` 核对（搜狗来自 rime-ice 的整理），每套方案对全部音节做往返测试；微软与搜狗只差微软的 `v` 键兼作 üe。
开着时缓冲区里存的仍是敲的键，Engine 在切分前把键两两配对解成全拼（音节之间自动带 `'`，没有切分歧义），
之后查词、整句、学习全部走全拼那一套：拼音行显示解出来的全拼（`nihc` → `ni'hao`），学习按全拼记（`user-choices.tsv` 的键与全拼共用，切回全拼也受益），
上屏消耗按「候选盖住几个音节、每个音节几个键」换算回缓冲区（`kdfave` 选 开发 吃掉 4 个键，剩 `ve`）。
末尾落单的一键当声母 / 元音前缀出简拼候选（`kdf` → kai f…）；配不出音节的键起原样留作尾巴（`nibl` → `ni'bl`）。
零声母：小鹤 / 自然码写 `aa` `ai` `ah`（a、ai、ang）一族，微软 / 搜狗写 `o` + 韵母键（`oa` `ol` `oh`），双写元音的写法也认。
微软 / 搜狗的 `;` 是 ing：组句中末尾有落单声母时敲 `;` 进缓冲区（`x;` → xing），其他时候仍是标点，壳问 `Engine::takes_semicolon`。

拼写纠错停用：敲错一键换掉的是整个声母 / 韵母，
全拼的一处编辑模型不适用。回车仍原样上屏敲的键；全部键都能解成完整音节的串（`nihc`）不记进个人英文词表，解不干净的（`gist`、`hello`）照记。
快捷候选（`rq` `sj` `xq`）与英文候选仍按敲的键认。
已知：`lue` / `nue` 与 `lve` / `nve` 同键，解成 v 的写法，词库里少量 `lue` 读音的词双拼下打不出（待把词库统一成 v）；`lo` 与 `luo` 同键，解成 luo。

### 快捷候选（rq / sj / xq）

Core `shortcut` 模块，不查词库、由输入直接算出，`CandidateKind::Shortcut`，上屏吃掉整段作用域、不记学习：

- `rq` / `sj` / `xq`：今天的日期（`2026年9月3日`、`2026-09-03`、`2026/09/03`）、现在的时间（`19:06`、`19:06:23`、`19点06分`）、
  星期（`星期四`、`周四`），插在本地首选之后（首选仍是 日期 / 时间 / 需求 这类词库词）。



### 设置程序

配置文件 `config.toml` 是唯一事实源；设置程序、手改文件、托盘菜单三个入口都只写它，Server 热加载
（保存后一秒内生效，不用重切输入法）。

设置程序缺省是 egui（`apps/windows/settings-egui/`），窗口 700×560：左侧 168 pt 导航，右侧当前页；一页一张紧凑列表卡，
每项 38 pt 高，左边图标、中间标签、右边控件，说明放在标签与 `ⓘ` 的悬停提示里。没有「保存」按钮，改完立即写回并生效。
系统标题栏关闭，`title_bar.rs` 自绘品牌标题、拖动区、最小化 / 最大化 / 关闭按钮；标题栏与正文同步使用当前色系。
排版取值集中在 `widgets/`，配色集中在 `theme.rs`。

`[general] font` 同时用于设置正文、主题卡示例文字、候选窗口与悬浮状态条。Segoe Fluent Icons 另登记成专用 `zizai-icons` 字族；
导航、设置行、说明记号都显式用它，不能经过 `FontId::proportional` 的用户字体回退链。状态条左侧拖拽 Logo 与设置齿轮继续用矢量绘制；普通背景上的「中 / A」与双拼单字仍走当前候选字体。

页序：通用 / 候选窗口 / 词库 / 高级 / 关于——项数只有一两条的分节（原先的「快捷键」「本地整句模型」「统计」）不单独占一页。
「通用」一张列表包括输入方案、按键、标点与候选质量；
「候选窗口」页首是奶油 / 字在蓝 / 紫藤拿铁 / 森林四张选择卡，每张由 egui painter 现场画浅 / 深两条候选预览，
预览文字使用当前字体；明暗始终跟随 Windows。下面一张列表是每页候选数 1–9、字体、拼音显示与悬浮状态条开关；
「词库」（「导入词库…」走系统打开文件对话框，接受字在 TSV / Rime `.dict.yaml` / `.qj`，
`qingjian_dictionary::import` 转成 `.qj` 放进用户目录 `dicts/`；下面列出每本附加词库：先是随包的领域词库（标「随包」，勾选写 `[dictionaries] domains`，
缺省只勾成语，不能移除），再是导入的（勾选写 `disabled`，名字 · 条数 · 许可证，「移除」把文件挪到 `dicts/removed/` 不真删））、
「高级」两组：文件与目录（打开配置文件 / 数据目录 / 日志目录、打包日志到桌面）、日志与诊断（详细日志、记录输入日志、清空输入日志）、
「关于」（大号 Logo、版本与构建号、官网与 GitHub、输入统计、许可证与随包数据来源、隐私与反馈）：

日志缺省 info 级，不含用户敲的内容；`[general] log_level = "debug"`（「高级」页「详细日志」）才逐键记，`tracing_subscriber::reload` 热切换，`RUST_LOG` 环境变量在时以它为准。

### 中英切换

单击 `Shift` 切中英；`Caps Lock` 是真正的大小写锁定，亮着时无论中英模式都直接输出大写英文。
英文模式默认小写、按住 `Shift` 大写。中文标点：`, . ? ! : ; ( ) [ ] < > \ ^ _ $ ~` 转全角，`"` `'` 成对切换；数字后的 `.` 保持半角。`-` `=` 不转换。

### 拼音行（preedit）

候选窗口顶部有一行 preedit：带 `'` 的切分拼音和我们自己画的光标。marked text 里的插入点由应用决定画不画，
终端和不少 Electron 应用不画，所以光标必须自己画。
Core 给的是分段（`Query::marked_segments`，`MarkedKind`：敲的拼音 / 光标后剩下的拼音 / 激活的辅码段 / 被纠错改掉的字母），
壳按段选样式（剩余部分与辅码段画淡，纠错改掉的画淡加删除线），光标位置按拼接后的字符数算。
辅码段要单独画：两码都敲完时解码把那 2 键剥掉了，不画的话敲进去的辅码一点痕迹都没有，
候选被严格过滤筛空了用户也看不出是为什么（`ni'hao rN`，空格隔开、原样保留大小写）。
只敲第一码时那一键还留在拼音里（`ljm` → `lan'm`，它同时还可能是下一个字的声母），不重复画；
那一档的反馈是候选顺序变了，外加候选右上角的辅码小字（见下）。

候选右上角用序号字号的淡色小字标「还要敲的码」（`Candidate::fuma` → `Row::corner`）：只敲了第一码时，
首码对上的候选标第二码（`栏ˢ 栏目ᵏ 榄ᵉ`），对不上的（蓝莓，`m` 是下一个字的声母）不标——有没有小字本身就区分了两种读法；
两码都敲完时候选已严格过滤、辅码段在拼音行里，不标。学码档（`[general] fuma_hint = "always"`）在没敲辅码时
也给每个候选标完整两码（`栏ᵐˢ`），给还没记住码的人。
小字跟在词后、同一行，不进 annotation：横排的 annotation 给高亮候选另起一行，它一出现 / 消失候选框高度就跟着变
（早先把辅码放在 annotation 里就是因此撤掉的，中间一版改成拼音行末尾只提示高亮候选的第二码，一次只能看到一个）。

### 拼写纠错

拼音「不像话」时（切不干净有尾巴，或非末尾的音节里有简拼 / 残缺）试一处编辑：相邻换位、换一个字母、多一个、少一个；
末尾是单字母时（`mingtai'n`，可能是合法简拼也可能是敲反了）只试相邻换位。只保留改完后每个音节都完整的变体，
再按噪声信道挑：每个变体跑一次整句转换，得分最高的那个还要**扣掉一次编辑的代价（`TypoCosts::correction_penalty`，5 nat）后仍高于原串按原样转出的得分**才纠
（`nihooma` → 你好吗，`woxiagnqu` → 我想去，`mingtain` → 明天，`nihaov` → 你好；原串切不干净就没有原样得分，能转出整句的纠正直接胜出）。
合法简拼（`nhao`、`womend`）原样与纠正后走的是同一条路径，扣掉代价就输了，不会被误纠；
整段本身是英文词的不纠（`hello` 不会变成 和咯）；「删掉刚敲的最后一个字母」不算纠正（`kaiv` 的 v 留作尾巴）；少于 4 个或多于 24 个字母不纠。
2026-09-05 之前的规则是「纠正后至少凑出一个两音节词」，语言模型把 你/好/吗、我/想/去 都切成单字路径，这条规则反而放行了 你/后妈、我/峡谷/区，已废。

**词图里的敲错边**（2026-09-06）：上面那路只管切不干净的输入；全部音节都合法、整句却说不通的（`meiganxi` 没敢洗）另有一路——
整句词图里每个完整音节除了敲的原样，还按它的一处敲错变体（相邻两键换位 `shou`→`shuo`、敲到相邻键 `ni`→`mi`、多一键 `gang`→`gan`、少一键 `gan`→`guan`；
`correction::typo`，只算合法音节，不算不相邻的键）查词，命中的词扣那类敲错的代价（换位 / 相邻键 5 nat，多键 / 少键 5.5，`TypoKind::cost`）。
Viterbi 按噪声信道挑路径：`meiganxi` 读成 没关系 只扣一次 5.5，仍高于 没/敢/洗 三个单字，就出 没关系；`meiganxie` 没感谢 原样说得通，不动。
词级候选**不**带敲错变体（`kaif` 会冒出 咖啡 挤掉更长的原样词），整句路径读出的一个词（没关系）作为词候选插到最前；
词级候选里有音节正好拼成整段输入的词时不许敲错边压过它（`jineng` 按 `jin'eng` 切时词图里读出 近藤，但 技能 正好拼成 `jineng`，退回原样路径）。
不到 4 个字母、双拼、非末尾带简拼的切分、整段一处编辑已生效的纠正后拼音都不加敲错边。
上屏时候选音节逐个对回敲的字母（`Engine::align`：原样、没打完、敲错变体、公共前缀），按敲的字母消耗，
靠敲错变体对上的 (敲的, 要的) 音节对记进**个人敲错表**（`user-typos.tsv`，`Learner::record_typo`），退格重选时退回；
接受整段一处编辑的纠正也记（编辑落在的那个音节，`Correction::typo_pair`）。以后那条边的代价按 min(ln(1 + 次数), 3) 打折，
整段纠错的编辑代价同样打折——习惯性把 `shuo` 敲成 `shou` 的人，几次之后 我说 就自然排上来。这就是「个人按键混淆模型」，不训练、在线计数。

纠正生效时候选全部来自纠正后的拼音，拼音行把被改掉的原字母画成删除线插在原位：`ni'h` ~~o~~ `ao'ma`；
选词按纠正后的音节消耗拼音，再按那处编辑换算回原串（多敲的字母跟着被吃掉）。**回车仍原样上屏** `nihooma`。
学习：选了纠正后的词按原输入串记选择（`user-choices.tsv`），下次同样敲错直接首选；回车原样上屏过的串记成 `<raw>`，以后不再纠它。
Core `correction` 模块只产生候选纠正，挑选与学习在 Engine 里。

**输入日志**（`[general] input_log`，缺省开）：每次上屏往数据目录的 `input-log.jsonl` 追加一行——`keys`（消耗掉的原始键）、`pinyin`（整段切分，纠错时是纠正后的）、
`corrected`、`text`、`source`（word / sentence / english / shortcut / custom / emoji / raw）、`index`（选的是查询时候选列表里第几个，
原样上屏为空）、`top`（查询时前 5 个候选）、`scheme`、`english`、`t`（本机时间）；退格撤销另记一行 `retract`，指回被撤销那条的 `id`。
只有敲的键与上屏的文字，不含应用里的上下文；只写本机，「高级」页可关可清，「关于」页隐私说明有写。用途：离线回放算首选命中率做排序 / 整句的回归评测，
以及个人模型（Phase 7）的训练对。回放工具是 CLI `--replay`（见 CLAUDE.md），首批 150 条：词首选 75%、前五 95%，整句首选 86%。Core `Engine` 在 `query` 时留摘要（`QuerySnapshot`）、上屏时凑成 `InputLogEntry` 交给 `InputLogger`（学习 crate 的 `InputLog` 落盘，攒 20 条刷一次，停用输入法时也刷）。

选错了词也有补救：上屏后马上把它整个退格删掉、重打同一段拼音换选别的词，上一次记的学习（选择次数、输入串选择、词转移）会退回去，
不用担心一次误按空格把错词教给输入法。

拼音显示在哪由 `[general] preedit` 定：`both`（缺省）行内 marked text 与窗口顶部都显示；`inline` 只在行内，窗口不带拼音行
；`window` 只在窗口，应用里一个字都不留——终端与部分 Electron 应用行内拼音画得难看时用。

这个模式随帧下发（`Frame::inline_preedit`，由 Server 按配置置位），DLL 是纯渲染端不读配置；`window` 时 DLL 压根不起 TSF 组句，
没有组句范围可当候选窗口的锚点，改用当前选区（插入点）量光标矩形，量不到再退回鼠标位置。
起一段组句时才做的那两件事（输入框私密判定、读光标前文）也就不能挂在「起组句」上，改成一段组句里只做一次。

组句期间其余编辑动作一律吞掉，否则应用会动光标、丢 marked text。
